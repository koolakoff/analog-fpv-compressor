# Требования первой версии

Дата фиксации: 2026-10-03.
Источник: весь чат «Сжатие аналогового FPV видео» (5 обсуждений)
([чат](https://chatgpt.com/c/6ac13181-c674-83ed-a991-43ee7c4b164e)).
Поздние уточнения имеют приоритет над ранними предложениями.
Основной документ с происхождением требований и обоснованиями:
[источник истины](source-of-truth.md). Этот файл — его краткое представление.

## Согласованная цель

Minimize encoded size while preserving navigational information: motion, scene
geometry and transient obstacles.

Из исходного DVR-файла получить максимально компактное видео. Сохранять помехи,
их математическую модель или синтетически возвращать шум не требуется.
Точная текстура травы вторична; движение дрона, взаимное положение объектов,
трубы и ветки, даже мелькнувшие на короткое время, важнее.
Обработка оправдана выигрышем в размере с учётом времени, нагрузки на CPU
и сложности проекта; улучшение внешнего вида само по себе не является целью.
Целевой размер и допустимая потеря полезных деталей пока не заданы численно.

## Рабочая архитектура из последнего обсуждения

1. `ffprobe`: свойства потоков, длительность, размер, FPS, разрешение,
   соотношение сторон и признаки interlace.
2. Быстрый анализ всего файла: поиск длительных участков полного белого шума
   и выделение участков с полезным изображением.
3. `idet` на нескольких участках полезного видео: проверка необходимости
   deinterlace, без слепого доверия флагам DVR.
4. Один финальный проход кодирования: вырезание подтверждённых no-signal
   интервалов → условный `bwdif` → `hqdn3d` → опциональный scale → SVT-AV1.
5. Отчёт о принятых решениях, вырезанных интервалах, размере и времени обработки.

HQDN3D — внешний фильтр шумоподавления; SVT-AV1 — кодировщик, используемый
через FFmpeg с `libsvtav1`. Они решают разные задачи.

## Вырезание no-signal

- Длительный полный снег между полётами, например при замене батареи,
  удаляется; сохранённые участки склеиваются по времени.
- Короткие помехи и изображение с различимыми объектами не должны автоматически
  считаться бесполезными. При сомнении участок сохраняется.
- Собственный небольшой классификатор: изменение между кадрами, временная
  корреляция, наличие крупной структуры; одного признака недостаточно.
- Нужны минимальная длительность, гистерезис и сохранение запаса вокруг переходов.
- Предложенные точки старта для эксперимента: grayscale 128×96 при 5–10 fps,
  оценка структуры на 16×12; подтверждение 0.5–1 с, запас 0.2–0.5 с.
  Это гипотезы для калибровки, а не утверждённые пороги.
- Чёрный/синий экран, замерший кадр и надпись NO SIGNAL — возможные расширения,
  не обязательная часть первой версии.

## Deinterlace и кодирование

- Рабочий режим по умолчанию: `deinterlace=auto`.
- Предложенная выборка `idet`: 3–5 полезных участков, суммарно 300–500 кадров;
  точные правила и обработку неопределённого результата проверить экспериментом.
- Progressive сохраняется без deinterlace. Для interlaced рабочий выбор —
  `bwdif` в режиме `send_field`, чтобы сохранить временную информацию полей.
  Это заменяет раннее предложение использовать `send_frame` по умолчанию.
- Автоматическое снижение FPS не входит в основной режим. Вариант 25/30p
  против 50/60p для interlaced проверить отдельно на препятствиях и движении.
- Один внешний denoiser: HQDN3D. Его сила определяется benchmark.
- Film grain отключён: `film-grain=0`, `film-grain-denoise=0`.
  Поддержку параметров проверить в выбранной сборке.
- Temporal filtering SVT-AV1 оставить на defaults установленной версии;
  версию и параметры записывать в отчёт.
- Начальная гипотеза для benchmark: CRF, preset около 6 с ограниченным
  сравнением 4/6/8, `yuv420p` для 8-bit DVR. Это заменяет ранний старт preset 4.
  Число CRF и окончательный preset пока не выбраны.
- Crop и scale применять лишь при подтверждённой пользе; не обрезать полезные
  объекты и OSD. Автоматический crop ещё не согласован.

## Границы первой версии

Собственный код: классификатор no-signal, управление pipeline и benchmark/отчёт.
Декодирование, deinterlace, denoise, scaling, motion estimation, кодирование
и контейнер обеспечивает FFmpeg/SVT-AV1.

Основные сравнения: HQDN3D OFF/ON, вырезание OFF/ON, SVT-AV1 против x265.
Второй encoder нужен сначала для исследования; его наличие в продукте
решается по результатам. Большой перебор фильтров не требуется.
VapourSynth, CNR4, BM3D, NLMeans, atadenoise, NL4D, нейросети, RF/IQ DSP
и Av1an не входят в обязательный pipeline V1.

## Решения, которые ещё нужно принять

Язык и упаковка приложения (Python + NumPy предложены для прототипа),
конкретный CLI и необходимость GUI; MP4 или MKV; сохранение/удаление аудио;
профили качества, CRF, crop/scale; пороги no-signal и fallback для `idet`;
численные критерии допустимого качества и времени обработки.
Ранний пример `-an` и иллюстративные размеры не считаются согласованными требованиями.
