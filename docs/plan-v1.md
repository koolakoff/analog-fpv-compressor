# План первой версии

Обновлён 2026-10-04. Требования, архитектура, параметры экспериментов и причины
решений описаны только в [источнике истины](source-of-truth.md).
Этот файл определяет порядок работ, результаты этапов и проверки.
Предложения по реализации ниже не являются новыми согласованными требованиями.

## Состояние и ближайший шаг

Инструменты подготовлены и проверены; [локальная среда](setup.md).
Код pipeline и benchmark ещё не написан, результаты сжатия не измерены.
Следующий шаг — паспорт двух AVI и выбор фрагментов для baseline.
Состав локальных образцов: [examples/README.md](../examples/README.md).

## 1. Описать и разметить образцы

Получить ffprobe JSON: потоки, длительность, codec, FPS, field order,
SAR/DAR и аудио. Просмотреть записи и разметить полезное видео, полный снег
и переходы. Название файла не считать доказательством содержимого.

Результат: воспроизводимый паспорт и ручная разметка.
Для сравнения выбрать несколько отрезков примерно по 20–40 с:
чистый сигнал, помехи с полезной сценой, быстрое движение с препятствиями,
полный снег и границы его появления/исчезновения.

## 2. Выполнить baseline benchmark

Сделать отдельный исследовательский скрипт по D2, D3, D9 и D10
источника истины. Сохранять команды, версии, параметры и результаты,
достаточные для повторения сравнения. Не добавлять исследовательские варианты
в production автоматически.

Результат: таблица измерений и обоснованный выбор базовых настроек.
Просмотр полезных деталей проводится на одних и тех же исходных отрезках;
его выводы записываются вместе с измерениями.

## 3. Откалибровать NoSignalDetector

Реализовать метрики и автомат состояний по D7–D8. Сначала выводить
кандидаты/подтверждённые интервалы без изменения видео и сверять с разметкой.

Проверить снег в начале/середине/конце, возврат сигнала, быстрый разворот,
траву, краткую помеху, пустой/повреждённый вход и полностью no-signal файл.
Для последнего определить явное поведение без вводящего в заблуждение результата.

Результат: на размеченных образцах полезные участки не вырезаются.
Двух файлов недостаточно для заявления об универсальности; нужны и другие DVR.

## 4. Проверить interlace analysis

Реализовать выбор участков и интерпретацию idet по D5–D6.
Предусмотреть ручное переопределение и обработку неопределённого результата.
Проверить progressive и настоящий interlaced материал.

Результат: решение deinterlace с данными, позволяющими его объяснить.
Если среди наших образцов нет interlaced, явно отметить пробел в проверке.

## 5. Собрать управление pipeline

Реализовать архитектуру из источника истины и запуск FFmpeg.
Сначала реализовать общий контроллер, модель настроек и CLI по UI1–UI6/T1–T8;
проверить auto, ручные значения, off, валидацию конфликтов и поток событий.
Проверить `audio=remove` по умолчанию, `keep` с синхронной склейкой
и успешную обработку входа без аудиопотока.
Проверить английский язык CLI независимо от локали ОС и языка GUI.
Добавить консольный/файловый лог: сверить выбранные настройки и окончательные
таймкоды удаления с планом, проверить ошибку/отмену и недоступный каталог лога.
При склейке обеспечить корректные временные метки; если аудио сохраняется,
применить те же интервалы и проверить синхронизацию.
Не смешивать temporal-фильтрацией кадры разных полётов на стыке.

Предлагаемые средства контроля: анализ без записи видео, отключение вырезания
и HQDN3D, ручной deinterlace, воспроизводимая команда.
Сохранять исходники, не перезаписывать output молча, не выдавать незавершённый
файл за успешный; объяснять ошибки зависимостей.

Результат: запуск на полном AVI и отчёт с mapping исходных/выходных интервалов,
длительностью, размером, настройками и временем.

## 6. Добавить GUI над работающим CLI

Реализовать пользовательский сценарий из источника истины. Проверить равенство
фактических планов CLI и GUI для одинаковых настроек, отзывчивость при encode,
отмену задания, показ ошибок и открытие результата/отчёта.
Добавить каталоги переводов четырёх языков; проверить переключение/fallback,
перевод сообщений событий и размещение подписей на каждом языке.
GUI framework выбрать отдельно, после работающего CLI.

Результат: графический запуск того же pipeline без второй реализации обработки.
Batch, склейка входных файлов и разделение по полётам остаются будущими задачами.

## 7. Проверить полный результат и выбрать настройки V1

Измерить вклад вырезания и denoise на двух записях. Проверить декодируемость,
длительность, FPS, соотношение сторон, склейки и выбранную политику аудио.
Просмотреть полезные сцены и препятствия около границ вырезания.
Занести выбранные настройки и их основания в источник истины,
добавить инструкцию запуска в README.

Готовность V1: воспроизводимая обработка предоставленных образцов,
подтверждённый снег удалён, полезные участки сохранены, выигрыш и время измерены.
Численные критерии утверждаются после baseline.
